# Master edition and application handoff

Minimum edition record:

- master_id, subject_id, lane_id, version, as_of and audience;
- positioning_summary and selected_claim_ids;
- excluded_or_narrowed_claims with reason and fact_gap_ids;
- canonical_editorial_source and requested output formats;
- owner_review: proposed, approved or changes-requested;
- per-format check: produced, text-compared, rendered-reviewed or not-run;
- actual saved file identity, destination audience and readback result.

Separate status dimensions. Approved wording does not imply a saved file or a
transmitted attachment. A filename appearing in a folder does not prove that
its bytes match the source. A saved DOCX can remain an unapproved proposal.

Synthetic lane matrix:

| Lane | Select evidence | Exclude overstatement |
| --- | --- | --- |
| Enterprise architecture | supported integration and operating-model decisions | claiming an unheld chief architect title |
| Process improvement | actual workflow changes and adoption work | invented percentages or savings |
| Customer-facing engineering | demonstrated discovery and implementation work | calling a prototype a paid production deployment |
| AI adoption | documented pilots, tools and user enablement | implying enterprise-scale rollout from a personal demo |

These are examples, not required lanes. If two lanes use the same claims, show
how the audience and emphasis differ or ask whether one baseline would suffice.

Application handoff names exact opportunity identity, master edition and claim
IDs, the specific adjustments needed, recipient/audience and unresolved gaps.
The application owner retains exact submitted snapshots. A reusable master is
not a submission receipt. A consolidated coach revision is an alternative
edition to review, not automatic replacement of every role-family master.
