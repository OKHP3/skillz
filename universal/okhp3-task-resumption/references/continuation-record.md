# Continuation record

Use only the fields needed for the actual work. Keep private identifiers and
artifact locators within the authorized audience.

```text
Objective:
Original thread: exact ID, returned title, source and execution host
Observation time and history coverage:
Current human request and authorized action scope:
Preserved decisions, exclusions and user edits:

Work items:
  Identity:
  Last verified milestone and receipt:
  Current observation, source and date:
  Remaining work:
  Existing artifact/destination:
  Next action and owner:

Dispatch:
  Archive state before/after:
  Continuation prompt identity or host receipt:
  Outcome: not attempted / queued / running / completed / awaiting owner /
           denied / uncertain
  Evidence supporting that outcome:

Blocked action:
  Exact action, target, reason and source:
  State: denied / pending / uncertain
  What already completed:
  Independent work still possible:
  Required new evidence or owner action:
```

## Worked example

A user asks to restart an archived employer thread containing two requisitions.
History confirms one submitted application and one draft. Restore the exact
original and resume the draft only. The send returns a receipt; report running,
not both applications complete. If the draft needs sign-in, finish independent
document work, preserve the confirmed submission and return the authentication
block with the existing thread locator.

If only an old exported transcript is available, label its state historical.
Create a continuation record from that evidence; do not claim live restoration.
