# Depth labels and gap phrasing

Assign one label per claim. Write the label's meaning in plain words in the
addendum rather than the label itself.

| Label | Meaning | Plain-language phrasing |
|---|---|---|
| Designed and built | The candidate made it and it ran | "I built", "I designed" |
| Hands-on | Used it directly in real work | "I used X several times a week" |
| Evaluated | Assessed it against alternatives, not in production | "I evaluated X with real requirements; it never went to production" |
| Contributed | Part of a team effort, not the lead | "I contributed to" |
| Knowledge only | Understands the framework, has not owned it | "I understand X and the data it depends on; I haven't owned the program" |
| None | No evidence | State as a gap and a ramp area |

## Rules

- Never upgrade a label to improve fit. A shallower honest label survives
  reference checks; an inflated one does not.
- A personal or prototype build is not an enterprise deployment. Say which.
- Acronyms and standards belong in the addendum only at the depth shown, such as
  "impact-analysis core of a business impact analysis" rather than "ran a BIA
  program."
- Name platform limits as ownership or funding facts, not as complaints about
  colleagues or tools.

## Gap phrasing

One sentence for the gap, one for the ramp area: "I haven't <X>. <Y> is the first
thing I would learn, and the underlying <Z> work is the same craft."
