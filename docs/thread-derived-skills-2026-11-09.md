# Thread-derived skill candidates

The owner requested extraction, equilibrium review and publication of useful
repeatable workflows from a conversation about dedicated AI infrastructure and
recovery of unfinished career work. The private conversation is a historical
design input, not evidence that the new packages completed those actions.

| Candidate | Why it is a skill | Disposition |
|---|---|---|
| Original-task resumption | A bounded trigger, supported history discovery, exact-thread restoration, authority preservation, duplicate prevention and verified outcomes | New `universal/okhp3-task-resumption` |
| Job application completion | A repeatable evidence-to-materials-to-submission workflow with exact identity, reviewed bytes, consent and receipt gates | New AskJamie canonical package, mirrored in `askjamie/okhp3-job-application-completion` |
| Résumé narrative drafting | Reusable evidence-to-role procedure | Reuse AskJamie `resume-representative` |
| Application status reconciliation | Evidence precedence and per-surface safe updates | Reuse existing AskJamie reconciliation package |
| Saved-opening triage | Listing inventory, fit assessment and employer handoff | Reuse existing AskJamie triage package |
| Headless AI capacity planning | Could become a workload-to-capacity decision procedure | Deferred: no measured workloads, verified current product dataset or repeatable benchmark protocol in the source |

Career workflows are not social-posting skills. No social package or unrequested
social content is created. Role identity and proof of submission are decision
rules inside application completion, not additional thin packages.

## Equilibrium findings and corrections

Evidence, outcome and safety/portability reviewers used separate contexts with
the same inherited model and sanitized source set. This reduces shared context,
but does not establish independent model or source diversity. They reviewed the
frozen 0.1.0 draft. Evidence review deferred until execution receipts existed;
outcome review allowed candidate publication with limits; safety review identified
missing explicit content-authority and concurrency boundaries. That is material
disagreement, so negotiation, rather than ceremonial dissent, is the release path.

Candidate 0.2.0 closes those specific gaps and adds regression cases. Prior 0.1.0
results are historical. The final record binds review, fixtures and structural
checks to exact 0.2.0 core hashes. No actual private applications or portals are
exercised in these tests.

## Release limits

Publication here means source packages are available in the repositories. It is
not a marketplace release, a production acceptance or an assertion of broad task
quality. The skills remain draftable. Discovery query sets are design-only; an
unseen release holdout and live host integration remain outstanding. A paired
synthetic exercise can expose decision failures, but its small visible set cannot
prove general uplift. Exact evidence and synchronization records accompany the
packages and release documentation.

The paired 0.2.0 exercise produced 15 decision records per configuration. A
separate grader, blinded to configuration identity, passed 47/47 expectations
with the skills and 47/47 without them. No uplift was demonstrated on this sample.
The package fixture records retain responses, strict grades, core hashes and
execution limits. The aggregate benchmark stays analytical to avoid implying
that any live portal action was exercised.

Local release checks passed: package structural checks, AskJamie manifest and
registry validation, 174 AskJamie repository tests, and 51 catalog tests after
incorporating concurrent changes. GitHub PR checks and post-publication readback
are separate gates. The independent review record is preserved under
`docs/skill-review-2026-11-09/`.
