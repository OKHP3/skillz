# Repo-settings authoring and review record

Candidate: okhp3-repo-settings 0.1.0. Local date: 2026-09-10.

## Architecture and acceptance

Outcome: configure one owner's GitHub repository with compatible safeguards,
provider-independent review, and verifiable settings without repeated generic
best-practice explanation. Inputs are repository identity, purpose, authority,
observed controls and workflows. Outputs are a recap and settings record.

Scope is single-repository configuration, not scaffold creation, code review,
merging, deployment, fleet cleanup, or paid integration provisioning. Target
clients are Agent Skills-compatible agents with optional authorized GitHub tools.
The knowledge advantage is the specific composition of solo approvals, actual
check coverage, combined Copilot controls, scoped automation claims, auto-merge
ordering, MCP/billing boundaries, and saved-state verification.

The author is the coordinating Codex context. Reviewers are separate read-only
contexts with a shared model family and overlapping source set; they are not
cross-model evidence. Development prompts and 20 discovery queries were designed
before external review. No with/without-skill trial or unseen holdout was run.

Acceptance for local routing: valid portable package; relative links and parseable
records; explicit authority and failure boundaries; accurate source-bounded claims;
creator composition; no material unresolved review defect; identical promoted
package bytes. Public release and performance claims are excluded.

The negotiator inspects this delta against the final inventory. Initial reviews

## Interpretation

Analytical review checks design and evidence boundaries. It does not prove live
configuration success, trigger precision, recall, uplift, cost savings, or safe
execution by every host. An external unseen holdout and version-specific execution
are required before making those claims. The source session predates the skill.

Reopen review after material skill edits, provider UI/billing drift, a changed
creator contract, deployment scope change, or a new failure case.
