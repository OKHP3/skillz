# Private evidence filing

Use only when the user requests a supporting artifact and identifies the
permitted storage roots or authorizes an established routing map. Check each
position or case independently. Keep log-edit and filing permissions separate.

1. Identify the artifact's purpose and position. Inspect the actual local or
   cloud root, destination audience and access, existing folders, and original
   evidence. Reuse an exact matching folder. Never use title similarity as a
   crosswalk or treat an unverified shared link as a trusted root.
2. Confirm the resolved destination stays within the approved root. For local
   files, verify the resolved parent at creation and reject symlink or traversal
   escapes. Stage the packet if containment cannot be assured.
   For cloud folders, verify the drive, item identity, ancestry, and audience.
   If a linked local mirror is involved, verify the mapping and account.
3. Make a folder only for a concrete position or separately authorized case
   and a nonempty packet. Use the owner-approved layout. When that layout
   designates a supporting-details folder, put the packet there. Keep originals,
   submitted snapshots, and existing evidence intact.
4. Save a short decision summary and source register with scope, safe
   locators, observed facts, and open gaps. Add byte lengths and SHA-256 when
   the local bytes are readable. Omit raw mail, unnecessary attachment
   contents, credentials, private join links, and sensitive personal details.
   Give the packet a stable run identity. Use exclusive creation or compare the
   existing packet by identity and bytes before reuse. Preserve conflicts for
   review. After a partial write, compare each existing item before resuming
   with missing items. Keep the packet unverified until readback is complete.
5. Read back the exact saved items. Record local bytes and checksums, cloud
   listing and size, and cloud content/hash verification separately. A cloud
   listing supports metadata presence. Claim remote byte equivalence only
   after inspecting the bytes or a trustworthy same-algorithm remote digest.
   Disclose blocked cloud reads or an unverified local-to-cloud mapping. Link
   the packet into an authorized private tracker only after its required
   verification passes.

Use synthetic examples in public skills, fixtures, review records, and issue
or pull request text. Exclude private source and destination identifiers,
accounts, subjects, filenames, links, roots, and source content.
