# Design and candidate decisions

Evidence status: analytical source candidate. Current version: 1.0.1.

## Outcome and knowledge advantage

Turn a one-sided notification feed into a bounded, bidirectional case status
without confusing notification arrival with message chronology. The specific
advantage is the event/request split, explicit outbound coverage, identity
crosswalks, distinct transmission milestones, and evidence-based next-action
ownership. This is repeatable across contacts, opportunities and review sessions;
it is not merely a summary style or a remembered personal fact.

Inputs: scoped live access or captured conversation, notification copies, review
clock and an optional existing private case record. Output: per-case delta,
open items, next owner, source coverage and uncertainty. Live connectors are
optional; a supplied capture remains usable within its recorded time window.

## Candidate disposition

| Candidate | Why it is reusable | Disposition |
|---|---|---|
| Bidirectional DM reconciliation | Corrects a repeated source asymmetry with stable evidence and output rules | New portable core; one canonical distribution source and an exact capability mirror |
| Recruiter/client/application milestone reconciliation | Distinct evidence rules separate a sent file from an onward submission | Compose with the existing application-status reconciliation package; no competing tracker |
| Career evidence addendum | Maps a targeted question to depth-qualified experience and a compact artifact | Existing career-addendum candidate has an upstream owner; do not duplicate it here |
| General thread closeout | Potentially repeatable, but much broader than the demonstrated DM correction | Reuse handoff/validation workflows; no new archive, merge or deletion authority |

The source was a user-supplied workflow retrospective. Only the abstract failure
and method were retained. Real people, organizations, files, message quotations,
private URLs and access details were excluded from this public package. No live
mailbox or LinkedIn access is needed to author or evaluate the synthetic cases.

## Review gaps and release limits

The original method lacked explicit outbound coverage, multiple-request
tracking, unambiguous duplicate linkage, temporal precision limits, distinct
submission milestones and a restart record. These are requirements of this
candidate and its regression design.

Structural validation and separated analytical reviews do not establish live
connector compatibility, automatic trigger precision/recall, task-quality uplift,
unattended monitoring, or production readiness. The development cases are
author-visible. A matched live benchmark and an external unseen holdout remain
not run. Release is limited to supervised source distribution.

## Change provenance

- User correction: incoming notifications omit outbound platform replies.
  Result: require both-direction coverage and explicit uncertainty.
- Repeated per-contact checks: chronological messages changed next-action
  ownership. Result: separate case, event and request records.
- Artifact follow-ups: permission and attachments do not prove client receipt.
  Result: keep transmission, content inspection and onward submission separate.
- Repository comparison: existing drafting and status packages already cover
  adjacent jobs. Result: narrow scope and link composition instead of cloning
  those workflows.

Freeze package hashes and evaluation expectations before independent review.
Record corrections and review decisions without presenting retrospective
reasoning as a fresh live benchmark.

## Review correction, 1.0.1

Independent analytical review found that fulfillment alone did not establish a
new obligation for the contact. The rule, worked example and fixtures now
distinguish explicit commitments, inferred dependencies, and no remaining
evidenced request. A paired no-follow-up fixture guards this boundary. Public
metadata uses string values; provenance and repository routing remain outside
the neutral package. The original-work license notice uses neutral attribution.
