---
name: Cross-artifact data sharing
description: How to share generated JSON data (e.g. a catalog) between two independently deployed artifacts in this monorepo.
---

When one artifact (e.g. forge-review-desk) needs to consume data generated by another artifact's build step (e.g. forge's `public/data/catalog.json`), do not rely on a live cross-origin `fetch` to the other artifact's dev/prod URL at runtime, even though Replit's path-based proxy makes that technically reachable in the dev workspace.

**Why:** Each artifact is an independently built and deployed static site (own `dist/public`, own production serve). A runtime fetch between them creates a hidden coupling that breaks standalone testing (a Playwright harness that spins up only the consuming artifact's dev server can't reach the other artifact's data) and is fragile across deployment topologies.

**How to apply:** Add a small `scripts/sync-<name>-data.mjs` in the consuming artifact that copies the source artifact's generated JSON into the consumer's own `public/data/` at build time, and wire it as a `predev`/`prebuild` script (pnpm auto-runs these before `dev`/`build`). The consumer then fetches its own same-origin copy via `${import.meta.env.BASE_URL}data/<file>.json`. Fail loudly (throw) if the source file is missing rather than silently skipping the copy.
