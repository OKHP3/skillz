---
name: Forge catalog/detail/search-index payload split
description: Why Skillz Forge's catalog.json no longer carries full skill body text, and where that text lives instead.
---

The main `catalog.json` payload (fetched by every route via `CatalogContext`) must never carry each skill's full body text again. It was previously embedded as `bodyText` on every skill object solely so Explore's search box could full-text search — but that meant Home, Compare, and family pages paid for content only Explore needed, on every load.

**Why:** first-load payload size should scale with what a route actually renders, not with the union of every page's data needs.

**How to apply:** body text lives in two separate, purpose-built, lazily-fetched assets generated by `build-catalog.js`:
- `data/search-index.json` — `{name, family, bodyText}` (markdown-stripped plain text) per skill, fetched only by Explore when a visitor searches.
- `data/skills/<family>/<name>.json` — `{name, family, rawBody}` (unstripped markdown, headings/links/code fences intact) per skill, fetched only by SkillDetail's Full Contract renderer when a visitor opens that skill.

If a new feature needs any skill's full text, add a new lazy fetch scoped to the page that needs it — do not add the field back to `catalog.json`.
